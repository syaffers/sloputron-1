# D-008 — Instruction set 1.0 for F1: branch on carry, carry shifts, load/store offset

**Status:** accepted, 2026-11-25 (proposed by Claude at the owner's request to "design the
final instruction set for F1 alone"; the owner may veto any part). **Builds on:** D-006
(F1 with 4 threads) and ISA 0.3 (Phase 3 "v3").

## Context
ISA 0.3 was shaped to run on two cores, F1 (barrel) and F5 (single thread). With F5 gone
(D-006), the open items in the 0.3 spec were:
- a 12-bit PC;
- unrolled kernels against code size;
- a multiply step or shift-by-N;
- load/store with an offset;
- customasm rules and C decode tables.

**Method.** Each candidate went into the benchmark core (`bench/rtl/r_f1.sv`, parameter
`X`, one bit per extension). The D-002 kernels were rewritten to use it
(`bench/kernels.py`), checked against the reference interpreter and the D-002 check
values, and run on the RTL. Each variant was then built over 16 nextpnr seeds in the
standard harness (OSS CAD Suite 2026-11-01, linux-aarch64). A pseudo-random hazard program
also exercises each extension. Nine mutants of the new logic were all caught.

The three extensions measured use encoding space that 0.3 left unused:

| Bit | Extension | Encoding | Hardware |
|---|---|---|---|
| B | **branch on C**: `bcs t`, `bcc t` | jump bits 12..11, which 0.3 ignored | the jump condition is resolved in S1, from the C that arrives with the PC |
| S | **carry shifts**: `shl`/`shr` set C to the bit shifted out; `rcl`/`rcr` shift C in | rs = 1 in the shift forms (0.3 required rs = 0) | a shift-in bit, and a C source |
| O | **load/store offset**: address = rs + k, k = 0–15 | bits 3..0 of `ld`/`st`, which 0.3 ignored | an adder on the data address |

## Measurements
F1, 4 threads, standard harness, 16 seeds. "Per clock" divides out Fmax: between these
variants Fmax moves by about ±3% with placement alone (the unchanged 0.3 core measured
90.0 MHz before and 92.2 MHz now). Score = iterations/s per 1000 cells, geometric mean
over the four kernels (D-002).

| Variant | Cells | Fmax median / worst | Speed per clock | Work per clock per cell | Score |
|---|---:|---|---:|---:|---:|
| 0.3 | 336 | 92.2 / 87.7 | 1.00 | 1.00 | 38,295 |
| + B | 338 | 95.6 / 90.2 | 1.11 | 1.10 | 43,708 |
| + S | 350 | 89.5 / 86.3 | 1.12 | 1.07 | 39,821 |
| + B + S | 348 | 93.2 / 90.8 | 1.26 | 1.21 | 46,896 |
| **+ B + S + O (1.0)** | **354** | **95.4 / 91.8** | **1.30** | **1.23** | **48,768** |

Per kernel, 1.0 against 0.3, cycles: crc16 1.38×, sort 1.14×, mul16 1.55×, memcpy 1.16×.

**Where each one helps:**
- **B** closes a counted loop in 2 instructions (`add rN, 1` then `bcc`, counting up from
  −n) instead of 3. It does little for sort: a skip over a `jmp` already costs one cycle,
  because the skipped word takes no cycle.
- **S** puts the bit that a shift drops into C, so `shl crc; skip cc; xor crc, poly` is one
  instruction shorter. mul16 becomes a right-shifting multiply: `shr b; skip cc; add hi, a;
  rcr hi; rcr lo` per bit.
- **O** lets sort keep the hole at j + 1 without a register, and mul16 read a pair with
  one pointer update. In the board's 12-bit address space the adder costs 11 cells
  (whole system 410 → 421), not 6.

**Unrolled kernels** (software only; X = 8 in `bench/`). These are not the scored
figures:

| | crc16 | mul16 | memcpy | Score | Code, 4 kernels |
|---|---:|---:|---:|---:|---:|
| 1.0, rolled | 1.38× | 1.55× | 1.16× | 48,768 | 119 words |
| 1.0, unrolled | 2.33× | 2.17× | 2.76× | 74,980 | 222 words |

(speed against 0.3 rolled; sort is not unrolled)

## Decision
1. **ISA 1.0 = 0.3 + B + S + O.** `isa/isa.toml` (version 1.0) is the spec. `rtl/core/f1_core.sv`
   implements it, and the board runs it.
2. **12-bit PC: no.** The jump's spare bits now hold the branch condition. The board's ROM
   is 4 KB (8 BRAMs), with one BRAM spare, so a larger program space would have no memory
   behind it.
3. **Multiply step: no.** A step that updates hi and lo writes two registers, and the
   register file has one write port. `rcr` gets mul16 to 1.55× without one.
4. **Shift-by-N: no.** A barrel shifter is 134 cells (`docs/phase2/primitives.md`), +40%
   of the core.
5. **Unrolling is a programming choice.** The scored kernels stay rolled, which keeps them
   comparable with every earlier figure. Unrolled versions are reported beside them with
   their code size.
6. **customasm: dropped.** It is not in the pinned toolchain, and `isa/asm.py` reads the
   spec directly. C decode tables will come with the C ISS that needs them.

## What this accepts
- **O is the marginal call.** In the scored, rolled kernels it gains 1.6% work per cell
  in the standard harness (+6 cells). In the board's 12-bit addresses it is about break-even
  (+11 cells). Two things carry it: it uses bits that were otherwise wasted, and unrolled
  copies gain 1.7× (memcpy).
- **Shifts now change C.** Code that kept C across a shift behaves differently from 0.3.
  None of the kernels or board programs did.
- **Reserved encodings:** jump condition 3 (jumps), the immediate forms of the shifts, and
  rs = 2–15 in the shift forms.

## Consequences
- `docs/isa/isa.md` and `rtl/core/isa_pkg.sv` are regenerated. The assembler accepts
  `ld rd, [rs+k]`, `bcc`/`bcs` and `rcl`/`rcr`, and `isa/iss.py` simulates them.
- `f1_core` is checked on the kernels with every extension (`make sim-f1_core`).
  `programs/stress.s` uses them on the board.
- The new figure for the record: **F1 with ISA 1.0, 354 cells, 48,768** (0.3: 38,295 in
  the same run).
